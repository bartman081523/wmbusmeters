# DevMind — working principles

A language-agnostic engineering mindset for working in this repository. This
complements `AGENTS.md` / `CLAUDE.md`; it is about *how to think* while making
changes, not a restatement of the build commands or conventions there.

- **Readability counts; simple is better than complex; DRY.** Prefer the
  simplest correct solution; factor out redundancy. Match the surrounding style
  (4-space indent, brace placement, naming — see Coding Conventions in
  `AGENTS.md`).
- **Specification before implementation.** Derive behaviour from EN 13757 / OMS
  (the standards); don't invent it. libmbus is a useful comparison but wmbusmeters
  implements more than it, so it is not authoritative here. See
  `docs/agents/research.md`.
- **Evidence before opinion.** Back every claim with a source or a test; never
  assert from memory.
- **Test everything that can break — test-first.** For decoding logic, write a
  failing unit test in `src/testinternals.cc` (add `X(name)` to `LIST_OF_TESTS`,
  implement `void test_name()` using `assert()`) or a `<test>` block in the
  relevant `drivers/src/*.xmq`, then implement until it passes.
- **Pragmatism over dogmatism.** Use the tools the project already uses (GNU
  autoconf, `make`, the `xmq` tool, `jq`) and match its idioms rather than
  importing a foreign style.
- **Surgical changes.** Change the minimum needed; do not reformat unrelated
  code; do not add comments that restate what the code does; do not rewrite code
  you do not yet understand — research it first (see `docs/agents/research.md`).
- **Problem decomposition.** Split work into small, independently testable
  units; pick the right data structure; consider complexity.
- **Respect the architecture.** Core lives in `src/`; meter drivers are
  declarative `drivers/src/*.xmq`; generated artifacts are
  `src/generated_database.cc` and `tests/generated_tests.xmq` (never hand-edited
  — regenerated by `cd drivers && make install`). Keep the contracts between
  these modules clear.
- **Debugging/profiling.** Isolate a reproducer before fixing; treat the root
  cause, not the symptom; profile before optimising.
- **Version control & collaboration.** One logical change per commit; clean
  history; small, focused PRs; respectful review. Conventional-Commit prefixes
  (`feat:`, `fix:`, `test:`, `chore:`, `build:`) are used (see Commit Message
  Style in `AGENTS.md`).
- **Stand on the shoulders of giants.** Reuse existing open-source solutions
  where appropriate and contribute back. (libmbus is a good comparison
  implementation; the OMS spec is a free entry point to EN 13757.)
